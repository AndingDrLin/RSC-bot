# 04 · 测试与验收标准

> 原则：**每个环节都必须能用一条命令、一组数字证明"做对了"**。不能量化的验收项不算验收项。
> 交易系统的事故成本不是"重跑一次"，而是"真金白银 + 不可回滚"，所以本文件的严格程度高于一般业务系统。

---

## 1. 测试金字塔（本项目的版本）

```
                 ┌──────────────────┐
                 │ L6 灰度实盘 5 天  │  真钱，最小敞口，人工签字
                 ├──────────────────┤
                 │ L5 影子模式 24h   │  真实行情，只产意图不下单
                 ├──────────────────┤
                 │ L4 回放/对拍      │  真实历史响应重放，逐字段比对
                 ├──────────────────┤
                 │ L3 集成（mock）   │  全链路 + 故障注入
                 ├──────────────────┤
                 │ L2 契约测试       │  真实响应快照，防上游改版
                 ├──────────────────┤
                 │ L1 单元测试       │  纯函数、状态机、计算
                 └──────────────────┘
```

| 层级 | 运行时机 | 耗时预算 | 失败含义 |
|---|---|---|---|
| L1 单元 | 每次提交 | < 30 s | 逻辑错，立即修 |
| L2 契约 | 每日 + 发版前 | < 60 s | 交易所改版了，**停实盘** |
| L3 集成 | 每次 PR | < 5 min | 组件协作错 |
| L4 回放 | 每日夜间 | < 30 min | 行为漂移 |
| L5 影子 | 变更前后各 24 h | 24 h | 信号层问题 |
| L6 灰度 | 里程碑 | 5 交易日 | 真实落差 |

## 2. 测试环境与数据

| 环境 | 交易所 | 资金 | 用途 |
|---|---|---|---|
| `unit` | 无 | 无 | 纯函数 |
| `mock` | `mock-exchange` 容器 | 虚拟 | 集成/故障注入 |
| `fixture` | 录制响应 | 无 | 契约/回放 |
| `paper` | **真实行情 + 本地撮合** | 虚拟 | 策略与执行联调（不下真单） |
| `shadow` | 真实行情 | 真实账户只读 | 影子模式（只读 state，不下单） |
| `live` | 真实 | 真实积分 | 灰度 |

**规则：任何自动化测试都不允许在 `live` 环境跑。** `live` 只能由人工触发，且客户端需带 `--i-understand` 显式确认。

## 3. 逐环节测试与验收

### 3.1 E0 基础设施（M0）

| 测试 | 方法 | 通过标准 |
|---|---|---|
| 一键启动 | `docker compose up -d` 后等 60 s | 5 个服务 `healthy`，`/healthz` 200 |
| 离线可测 | 断网执行 `pytest` | 全绿（仅 fixture/mock） |
| 配置校验 | 故意写错 `rules.yaml` | 启动失败并给出字段级错误 |
| 密钥不泄漏 | gitleaks + 日志正则扫描 | 0 命中 |
| 镜像可复现 | 两次 build 的 `sha256` | 一致（固定依赖版本） |

**验收门槛**：新机器从 `git clone` 到 `healthy` < 10 分钟，全程无手工步骤。

### 3.2 E1 交易所 SDK（M1）

| 用例 | 输入 | 期望 | 类型 |
|---|---|---|---|
| 邮箱登录成功 | 正确邮箱+密码 | 拿到 `_t` cookie，`/rsc/state.json?section=wallet` 200 | 契约 |
| 中文用户名登录 | `login=安定精神科主任` | 客户端**不应**这样发；若发则断言 400 且提示"用邮箱" | 单元 |
| 密码错误 | 错误密码 | 抛 `AuthError`（注意 HTTP 200 但 body 有 `error`） | 单元 |
| CSRF 过期 | mock 返回 403 | 自动刷新 token 并重试 1 次 | 集成 |
| 会话失效 | mock 返回 302 到 /login | 自动重登 + 重放原请求，调用方无感 | 集成 |
| 幂等下单 | 同 `request_id` × 3 | 只 1 个 order_id；`replayed` 正确 | 契约 |
| 限频 | 100 并发 | 出网 ≤ 30/min；队列不丢请求（除非超 deadline） | 集成 |
| 429 退避 | mock 连续 429 | 指数退避，不重试非幂等请求 | 集成 |
| 错误映射 | 409 `order_not_pending` | → `OrderNotPending`，不重试 | 单元 |
| 超时 | mock 延迟 10 s | 抛 `TimeoutError` 并记录 trace_id | 集成 |

**验收门槛**：
- `exchange/` 覆盖率：行 ≥ 85%，分支 ≥ 75%。
- **0 次**在测试中产生真实订单（用 spy 断言 `place_order` 调用次数）。
- 全部错误码映射表 100% 有单测（枚举驱动，少一个 case 测试就失败）。

### 3.3 E2 数据管道（M2）

| 测试 | 方法 | 通过标准 |
|---|---|---|
| 与官方对账 | 自建 5m bar vs `history.json?range=1d` | close 相对误差 < 1e-9，bar 数完全一致 |
| 缺口检测 | 随机删除 5% bar | 检出率 100%，缺口率计算准确 |
| DST 切换 | 2026-11-01（美）与 2026-10-25（欧） | 无重复/缺失 bar，时间戳单调 |
| 时区归一 | 混入 HKT/JST/CET 时间戳 | 全部转为 UTC，与源一致 |
| 幂等重写 | 同一分区重复写入 | 行数不翻倍，内容一致 |
| 闭市期异常 | 注入闭市期报价 | 标记 `quality_flag=suspect`，不进入因子计算 |
| 回补 | 删除 3 天数据后回补 | 与原始数据逐行一致 |

**验收门槛**：60 标的 × 5 日，缺口率 < 2%，对账误差 < 1e-9，DuckDB 查询 P95 < 100 ms。

### 3.4 E3 回测引擎（M3）

**黄金用例（20 个，手算）**：

| # | 场景 | 关键断言 |
|---|---|---|
| G01 | 1x 多单持有 1 天 | 盈亏 = ΔP × qty − 2×fee；与手算差 < 1e-12 |
| G02 | 10x 多单 | margin = notional/10；强平价 = avg×(1−0.75/10) |
| G03 | 20x 空单 | 强平价 = avg×(1+0.75/20) |
| G04 | 触发强平 | 权益 = 0.25×margin 时平仓，剩余 = 0 |
| G05 | 手续费精确 | `fee = gross × bps/10000`，1e-12 精度 |
| G06 | 部分平仓 | 剩余 qty/avg 正确 |
| G07 | 跨日持仓 | 结算无漂移 |
| G08 | 5% 漂移拒单 | 订单 rejected，资金未占用 |
| G09 | 10 秒撤单窗口 | 窗口外撤单返回失败 |
| G10 | 超时释放 | 30 min 后 reserved 归零 |
| G11 | high_risk 预算 | 两笔 20x 共用 25% 权益，第三笔被拒 |
| G12 | 方向冲突 | 已有 long 再开 short → 拒绝 |
| G13 | 杠杆不一致加仓 | 拒绝 |
| G14 | 最小数量取整 | 0.007 → 拒绝或按 step 向下取整 |
| G15 | 最小名义 1 RSC | 0.5 RSC 股票单拒绝 |
| G16 | 多市场时段 | 休市订单拒绝 |
| G17 | 延迟品种信号 | 15 分钟延迟标的不接受 < 1h 信号 |
| G18 | 组合权益 | 多标的 pnl 加总正确 |
| G19 | 权重约束 | 单标的超 25% 被裁剪 |
| G20 | 空仓 | 全平后 equity = balance，无残留 |

**验收门槛**：
- 20/20 通过，误差 < 1e-12（金额）/ < 0.5 bp（价格）。
- 用账户中真实 25 笔成交回放，模拟成交价误差 < 0.5 bp、费用完全一致。
- 100 万 bar 回测 < 60 s，内存 < 2 GB。
- 同配置两次运行结果 bit-level 一致。

### 3.5 E4/E5 执行与风控（M4）

**故障注入目录（20 个场景，必须全部通过）**：

| # | 注入 | 期望行为 |
|---|---|---|
| F01 | 下单超时 | 不重复下单；用 `request_id` 查询确认 |
| F02 | 下单返回 500 | 指数退避重试 3 次后放弃并告警 |
| F03 | 429 | 排队等待，不丢单 |
| F04 | 响应体损坏（非 JSON） | 捕获并降级，不崩溃 |
| F05 | 状态延迟（下单后 60 s 才 filled） | 跟踪器继续轮询，不误判失败 |
| F06 | 部分成交 | 记录剩余量并按策略处理 |
| F07 | 价格漂移 > 5% | 收到 rejected，释放资金，记录原因 |
| F08 | 休市下单 | 前置拦截，不发请求 |
| F09 | 余额不足 | 前置拦截 |
| F10 | 持仓已达上限 | 前置拦截 |
| F11 | 方向冲突 | 前置拦截 |
| F12 | 杠杆超限 | 前置拦截 |
| F13 | 重复意图 | 分布式锁保证只下 1 单 |
| F14 | 会话失效 | 自动重登，订单不丢 |
| F15 | 磁盘满 | 降级为只平不开，告警 |
| F16 | Redis 挂 | 限频退化为进程内令牌桶（更保守） |
| F17 | 交易所改字段 | 契约测试失败，**熔断停止交易** |
| F18 | 连续亏损 5 笔 | 熔断，停止开仓 |
| F19 | 限频使用率 > 80% | 降级：只保留 P0/P1 请求 |
| F20 | 进程被 kill | 重启后从 SQLite 恢复状态，对账通过 |

**验收门槛**：20/20；每个场景都有对应断言与审计记录；**不允许"静默失败"**（无日志、无指标）。

### 3.6 E6 组合与资金（M4/M5）

| 测试 | 通过标准 |
|---|---|
| 保证金预算 | 总 margin ≤ equity × max_gross_leverage，超限拒绝 |
| high_risk 专项 | 杠杆 > 10x 的合计 margin ≤ equity × 25% |
| 相关性集中 | 同交易所/同行业超限时裁剪并记录原因 |
| 强平优先 | 多标的同时接近强平时，按风险排序平仓 |
| 日亏损熔断 | 达到阈值后当日不再开仓，次日自动恢复 |

### 3.7 E7 策略与回测结论（M5）

| 指标 | 门槛 | 说明 |
|---|---|---|
| 样本外 Sharpe（扣费） | > 0.8 | walk-forward，最后 20% 数据完全不参与调参 |
| MaxDD | < 20% | 含强平 |
| Calmar | > 0.5 | |
| 换手率 | < 5×/日 | 高换手必然被 20bp 成本吃掉 |

## 9. CI 流水线

```yaml
stages:
  - lint:      ruff, mypy --strict（src/）
  - unit:      pytest -m "not slow"  --cov-fail-under=80
  - contract:  pytest tests/contract   # 每日定时也跑一次
  - integration: pytest tests/integration  # 起 mock-exchange
  - replay:    pytest tests/replay --slow   # 夜间
# 当前实现是 unittest（零依赖）：PYTHONPATH=src python -m unittest discover -s tests -t .
  - security:  gitleaks, pip-audit, trivy
  - build:     docker buildx（多阶段，缓存）
  - smoke:     compose up + 健康检查 + 只读探针
```

**门禁**：`main` 必须全绿；覆盖率下降 > 2% 阻断合并；契约测试失败**自动禁用实盘开关**（把 `live_enabled=false` 写进配置中心并告警）。

## 10. 缺陷分级与里程碑退出标准

| 级别 | 定义 | 例 |
|---|---|---|
| P0 | 资金/持仓错误、重复下单、静默失败 | 对账差异、下错方向 |
| P1 | 功能不可用、熔断失效、限频超限 | 会话失效不重登 |
| P2 | 指标错误、告警缺失、数据缺口 | K 线少 3% |
| P3 | 体验/日志/文档 | 日志字段缺失 |

**里程碑退出**：无 P0/P1 未修复；P2 ≤ 3 个且有排期；P3 不计。

## 11. 常见"假验收"陷阱（自查清单）

- ❌ "回测跑通了" → 必须看**扣费后**、**样本外**、**含滑点**的数字。
- ❌ "接口调通了" → 必须有**幂等、重试、限频、错误码**的用例。
- ❌ "策略盈利了" → 必须有**多重检验校正**与**参数稳健性**。
- ❌ "监控有了" → 必须演练过**告警真的能叫醒人**。
- ❌ "部署成功了" → 必须有人按文档在**干净机器**上重来一次。
